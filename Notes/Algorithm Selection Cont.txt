USING THE STACK AS AN ANALYTICAL TOOL

A stack is not only a data storage structure but also a powerful problem-solving tool.

------------------------------------------------------------
WHY STACKS ARE USEFUL

Stacks simplify many programming tasks.
Instead of manually tracking data positions and indexes, the stack automatically manages insertion and removal operations.

Benefits:
• Simpler code
• Easier debugging
• Better organization
• Reduced programming errors

------------------------------------------------------------
STACK AS AN ANALYTICAL TOOL

A stack allows programmers to focus on problem-solving instead of managing data locations.

Without a Stack:
• Manually track indexes
• Handle insertions
• Handle deletions
• Maintain bookkeeping variables

With a Stack:
• Push()
• Pop()
• Peek()

Everything becomes simpler.

------------------------------------------------------------
COMMON APPLICATIONS OF STACKS

• Delimiter Matching
• Expression Evaluation
• Function Calls
• Recursion
• Undo Operations
• Browser History

------------------------------------------------------------
EFFICIENCY OF STACKS

Stacks are extremely efficient because operations occur only at the top.

5.2 QUEUES

A queue is a linear data structure that follows the First-In, First-Out (FIFO) principle.

Definition:
The first element inserted is the first element removed.

------------------------------------------------------------
FIFO PRINCIPLE

FIFO stands for:

First In, First Out

Meaning:

First Item Added
        ↓
First Item Removed

------------------------------------------------------------
QUEUE EXAMPLE

Think of a ticket line.

Front                               Rear

[A] [B] [C] [D]

Person A arrives first.

Person A gets served first.

------------------------------------------------------------
STACK VS QUEUE

Stack:

LIFO

Last In → First Out

Example:
Pile of Plates

------------------------------------------------------------

Queue:

FIFO

First In → First Out

Example:
Waiting Line

------------------------------------------------------------
WHY QUEUES ARE NEEDED

Queues are useful whenever tasks must be processed in order.

Applications:
• Print Queues
• Task Scheduling
• Keyboard Input Buffers
• Network Packets
• Customer Service Systems

------------------------------------------------------------
REAL-LIFE EXAMPLE

Bank Queue

Front                       Rear
John → Mary → David → Sarah

Service Order:
1. John
2. Mary
3. David
4. Sarah

------------------------------------------------------------
QUEUE OPERATIONS

Main Operations:
• Enqueue
• Dequeue
• Peek

------------------------------------------------------------
ENQUEUE OPERATION

Enqueue means adding an item to the rear of the queue.

Example:

Queue:
Front      Rear

10   20   30

Enqueue 40

Result:

Front           Rear

10   20   30   40

------------------------------------------------------------
DEQUEUE OPERATION

Dequeue means removing an item from the front.

Example:

Queue:

Front           Rear

10   20   30   40

Dequeue

Result:
Front      Rear
20   30   40

Removed: 10

------------------------------------------------------------
PEEK OPERATION

Peek returns the front element without removing it.

Example:
Queue:
Front           Rear
10   20   30   40

Peek Result: 10
Queue Remains Unchanged

------------------------------------------------------------
QUEUE IMPLEMENTATION

Queues can be implemented using:

• Arrays
• Linked Lists

------------------------------------------------------------
ARRAY IMPLEMENTATION

Example:
Index   Value
0       10
1       20
2       30

Advantages:
• Easy implementation

Disadvantages:
• May require fixed size

------------------------------------------------------------
LINKED LIST IMPLEMENTATION

Each node contains:
• Data
• Reference to next node

Advantages:
• Dynamic size
• Flexible memory usage

------------------------------------------------------------
CIRCULAR QUEUE

A circular queue reuses empty spaces created at the beginning of the array.

------------------------------------------------------------
PROBLEM WITH NORMAL ARRAY QUEUE

After several deletions:
Front → moves right
Rear → continues moving right

Eventually:
Rear reaches the last index
Even though empty spaces exist at the front.

------------------------------------------------------------
SOLUTION: CIRCULAR QUEUE

Instead of stopping: Rear wraps around to the beginning.

Example:
Array Size = 5
Index: 0 1 2 3 4
Rear reaches index 4

Next insertion:
Rear returns to index 0

Result: Array space is reused efficiently.

------------------------------------------------------------
QUEUE TIME COMPLEXITY

Operation          Complexity

Enqueue            O(1)
Dequeue            O(1)
Peek               O(1)
Search             O(n)

------------------------------------------------------------
WHY QUEUE OPERATIONS ARE FAST

Insertion occurs only at rear.
Removal occurs only at front.
No shifting is required.

------------------------------------------------------------
ERROR CONDITIONS

QUEUE OVERFLOW
Occurs when attempting to insert into a full queue.

Example:
Capacity = 5
Queue Already Contains 5 Items
Enqueue New Item

Result: Overflow Error

------------------------------------------------------------
QUEUE UNDERFLOW

Occurs when attempting to remove from an empty queue.

Example:
Queue Empty
Dequeue

Result: Underflow Error

------------------------------------------------------------
PRIORITY QUEUES

A priority queue is a special type of queue where elements are processed according to priority.

------------------------------------------------------------
WHAT IS A PRIORITY QUEUE?

Items are removed based on priority rather than arrival order.
Highest Priority Item → Removed First

------------------------------------------------------------
NORMAL QUEUE

Arrival Order: 10 → 20 → 30 → 40
Removal Order: 10 → 20 → 30 → 40
FIFO

------------------------------------------------------------
PRIORITY QUEUE

Items:
20
5
50
10

Removal Order: 5 → 10 → 20 → 50
Highest Priority Processed First

------------------------------------------------------------
REAL-LIFE EXAMPLE

Hospital Emergency Room

Patients:
Patient A → Minor Injury
Patient B → Heart Attack
Patient C → Fever

Treatment Order:
Patient B
Patient C
Patient A

Reason: Priority, not arrival time.

------------------------------------------------------------
HOW PRIORITY QUEUES WORK

Elements remain sorted based on priority.

Example:
Queue: 50 40 30 20 10
Highest Priority: 10
Removed First

------------------------------------------------------------
PRIORITY QUEUE OPERATIONS

Insertion: Place item in correct sorted position.
Deletion: Remove highest-priority item.
Peek: View highest-priority item.

------------------------------------------------------------
INSERTION IN PRIORITY QUEUE

Example:
Current Queue: 500 400 200 100
Insert: 300
Result: 500 400 300 200 100

------------------------------------------------------------
WHY INSERTION IS SLOWER

To maintain order:
• Search required
• Elements may need shifting

Time Complexity: O(n)

------------------------------------------------------------
DELETION IN PRIORITY QUEUE

Highest-priority item already sits at the front.

Example:
500 400 300 200 100
Delete: 100

Result: 500 400 300 200

------------------------------------------------------------
WHY DELETION IS FAST

Item is already positioned correctly.
No searching required.
Time Complexity: O(1)

------------------------------------------------------------
PRIORITY QUEUE TIME COMPLEXITY

Operation          Complexity
Insertion          O(n)
Deletion           O(1)
Peek               O(1)

------------------------------------------------------------
USES OF PRIORITY QUEUES
