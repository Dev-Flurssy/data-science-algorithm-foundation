TREES

A Tree is a non-linear data structure used to store data in a hierarchical form.
Unlike arrays, stacks, queues, and linked lists, tree elements are not stored sequentially.

A tree consists of:
• Nodes (Vertices)
• Edges (Branches/Arcs)

------------------------------------------------------------
WHY TREES ARE NEEDED

Linear Data Structures: Store data in a sequence.
Array
Linked List
Stack
Queue

Example:
CEO
Manager
Employee

Representing hierarchy becomes difficult.

------------------------------------------------------------
PROBLEM

Suppose a company has:

CEO
├── Manager A
│   ├── Employee 1
│   └── Employee 2
└── Manager B
    ├── Employee 3
    └── Employee 4

A linear structure cannot efficiently represent this hierarchy.

------------------------------------------------------------
SOLUTION

TREE
          CEO
         /   \
     Mgr A   Mgr B
      / \     / \
    E1  E2  E3  E4

Meaning: One node can have multiple children.

------------------------------------------------------------
DEFINITION OF TREE

A Tree is a finite set of one or more nodes in which:
1. One node is designated as the Root.
2. Remaining nodes form subsets called Subtrees.
3. Each subtree is itself a tree.

------------------------------------------------------------
TREE STRUCTURE

            1
          / | \
         2  3  4
         |     / \
         5    6   7

------------------------------------------------------------
TREE VS GRAPH

TREE
• A node can have multiple successors.
• A node can have only one predecessor (parent).

Example:
      1
     / \
    2   3

------------------------------------------------------------
GRAPH

• A node can have multiple successors.
• A node can have multiple predecessors.

Example:
A ---> B
|     /
v    /
C <--D

------------------------------------------------------------
TREE TERMINOLOGY

1. ROOT
Definition: Node that has no parent.

Example:
      1
     / \
    2   3

Root = 1

------------------------------------------------------------
2. CHILD

Definition: A node directly connected below another node.

Example:
      1
     / \
    2   3

Children of 1: 2, 3

------------------------------------------------------------
3. PARENT

Definition: A node directly connected above another node.

Example:
      1
      |
      2

Parent of 2 = 1

------------------------------------------------------------
4. DEGREE

Definition: Number of children of a node.

Example:
      1
    / | \
   2  3  4

Degree(1) = 3

------------------------------------------------------------
5. SIBLINGS

Definition: Nodes having the same parent.

Example:
      1
    / | \
   2  3  4

Siblings: 2, 3, 4

------------------------------------------------------------
6. DESCENDANT

Definition: A node reachable by moving downward.

Example:
      1
      |
      2
      |
      5

Descendants of 1: 2, 5

------------------------------------------------------------
7. ANCESTOR

Definition: A node reachable by moving upward.

Example:
      1
      |
      2
      |
      5

Ancestors of 5: 2, 1

------------------------------------------------------------
8. LEAF NODE (TERMINAL NODE)

Definition: Node having no children.

Example:
      1
     / \
    2   3

Leaf Nodes: 2, 3
Degree = 0

------------------------------------------------------------
9. INTERNAL NODE (NON-TERMINAL NODE)

Definition: Node with at least one child.

Example:
      1
      |
      2
      |
      5

Internal Nodes: 1, 2

------------------------------------------------------------
10. FOREST

Definition: A collection of separate trees.

Example:
Tree 1          Tree 2

  1              A
 / \            / \
2   3          B   C

Together form a Forest.

------------------------------------------------------------
BINARY TREE (BT)

A Binary Tree is a special tree in which each node can have:
• Left Child Only
• Right Child Only
• Both Left and Right Child

Maximum: 2 children per node
Example:
        1
      /   \
     2     3
    / \   /
   4   5 6

------------------------------------------------------------
ABSTRACT DATA TYPE OF BINARY TREE

OPERATIONS

create():Creates an empty binary tree.

makeBT(lbt, data, rbt): Creates a binary tree using:
• Left Subtree
• Root Data
• Right Subtree

isEmpty(): Returns:
True  -> Tree Empty
False -> Tree Not Empty

lchild(): Returns left child of a node.

rchild(): Returns right child of a node.

------------------------------------------------------------
TYPES OF BINARY TREES

----------------------------------
1. LEFT-SKEWED BINARY TREE

Definition: Every node has only a left child.

Example:
      1
     /
    2
   /
  3

Characteristics:
• No right child
• Looks like a linked list

------------------------------------------------------------
2. RIGHT-SKEWED BINARY TREE

Definition: Every node has only a right child.

Example:
1
 \
  2
   \
    3

Characteristics:
• No left child
• Looks like a linked list

------------------------------------------------------------
3. STRICTLY BINARY TREE

Definition: Every node has:
Exactly 2 children OR No child

Example:
          8
        /   \
       4     9
      / \   / \
     2   6 3  10

No node has only one child.

------------------------------------------------------------
4. FULL BINARY TREE

Definition: A Binary Tree in which:
• Every internal node has 2 children.
• All leaf nodes are at the same level.

Example:
            A
          /   \
         B     C
        / \   / \
       D   E F   G

Characteristics

Every node has:
0 or 2 children

----------------------------------
FORMULA
If:
h = Height
n = Total Nodes

Then:
n = 2^(h+1) - 1

----------------------------------
HEIGHT FORMULA
h = log₂(n + 1) - 1

Example
h = 3
n = 2^(3 + 1) - 1
n = 16 - 1
n = 15

------------------------------------------------------------
5. COMPLETE BINARY TREE

Definition: All levels are completely filled except possibly the last level.
The last level is filled from left to right.

Example:
          A
         / \
        B   C
       / \ /
      D  E F

Characteristics

• Last level filled left to right.
• Levels above are completely filled.

------------------------------------------------------------
IMPORTANT POINT

Every Full Binary Tree is a Complete Binary Tree.
BUT
Every Complete Binary Tree is NOT a Full Binary Tree.

------------------------------------------------------------
THEOREM 1: MAXIMUM NODES AT LEVEL i

Formula:
Maximum Nodes = 2^(i-1)

Examples
Level 1 = 2^0 = 1
Level 2 = 2^1 = 2
Level 3 = 2^2 = 4
Level 4 = 2^3 = 8

------------------------------------------------------------
THEOREM 2: LEAF NODE FORMULA

For Any Non-Empty Binary Tree
n₀ = n₂ + 1

Where:
n₀ = Number of Leaf Nodes
n₂ = Number of Nodes with Degree 2

Example
          A
        /   \
       B     C
      / \   / \
     D  E  F  G

----------------------------------
Leaf Nodes:
D, E, F, G
n₀ = 4

----------------------------------
Degree 2 Nodes:
A, B, C
n₂ = 3

----------------------------------
Check:
n₀ = n₂ + 1
4 = 3 + 1
TRUE

------------------------------------------------------------
COROLLARY

For a Strictly Binary Tree
Number of Leaf Nodes
= Number of Internal Nodes + 1

------------------------------------------------------------
THEOREM 3: VERTEX-EDGE RELATIONSHIP

Formula:
V = E + 1

Where:
V = Number of Vertices (Nodes)
E = Number of Edges

Example
      A
     / \
    B   C

Vertices = 3
Edges = 2

Check:
3 = 2 + 1
TRUE

APPLICATIONS OF TREES

• File Systems
• Company Hierarchies
• XML Documents
• HTML Documents
• Database Indexing
• Binary Search Trees
• Expression Trees
• Decision Trees
• Artificial Intelligence
• Operating Systems
• DNS Hierarchy

------------------------------------------------------------
ADVANTAGES OF TREES

• Represents hierarchical data naturally.
• Fast searching and retrieval.
• Dynamic structure.
• Efficient insertion and deletion.
• Used in databases and operating systems.
• Suitable for large hierarchical datasets.

------------------------------------------------------------
DISADVANTAGES OF TREES

• More complex than arrays and linked lists.
• Requires extra memory for links/pointers.
• Balancing may be required.
• Traversal algorithms can be complex.
