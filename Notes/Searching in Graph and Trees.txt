SEARCHING IN GRAPHS

Graphs are powerful data structures used to represent relationships between data.
A graph consists of vertices (nodes) connected by edges.

------------------------------------------------------------
WHY GRAPHS ARE USED

Graphs are used whenever relationships between objects need to be represented.

Examples:
• Social Networks
• Road Maps
• Biological Databases
• Web Pages
• Computer Networks
• Recommendation Systems

------------------------------------------------------------
GRAPH STRUCTURE

Example:
      A
     / \
    B---C
     \
      D

Vertices: A, B, C, D
Edges: AB, AC, BC, BD

------------------------------------------------------------
GRAPH COMPONENTS

Vertex (Node) → Represents an object or data item
Edge → Represents the relationship between objects

------------------------------------------------------------
WHY SEARCHING IN GRAPHS IS IMPORTANT

Graph searching helps answer questions such as:
• Are two graphs identical?
• Does a graph contain a certain pattern?
• Does a graph contain a smaller graph?
• Are two structures similar?

------------------------------------------------------------
REAL-WORLD APPLICATIONS

Biological Databases
Vertices: Atoms
Edges: Chemical Bonds
Purpose: Compare molecular structures.

Web Search Engines
Vertices: Web Pages
Edges: Hyperlinks
Purpose: Determine page relevance.

Computer Vision
Vertices: Image Regions
Edges: Relationships between regions
Purpose: Pattern recognition.

Network Systems
Vertices: Computers
Edges: Connections
Purpose:Route discovery and analysis.

------------------------------------------------------------
EXACT MATCH (GRAPH ISOMORPHISM)

Graph Isomorphism determines whether two graphs are structurally identical.
Two graphs are isomorphic if their vertices and edges can be matched exactly.

------------------------------------------------------------
EXAMPLE

Graph 1
A ----- B
|       |
|       |
C ----- D

Graph 2
P ----- Q
|       |
|       |
R ----- S

Observation
A ↔ P
B ↔ Q
C ↔ R
D ↔ S

Both graphs have identical structures.
Result: Graphs Are Isomorphic

------------------------------------------------------------
PURPOSE OF GRAPH ISOMORPHISM

Used to identify:
• Similar network structures
• Similar molecules
• Similar visual objects

------------------------------------------------------------
COMPLEXITY

Very difficult problem.
Category: NP Problem

------------------------------------------------------------
SUBGRAPH EXACT MATCHING: (SUBGRAPH ISOMORPHISM)

Determine whether a smaller graph exists inside a larger graph.

------------------------------------------------------------
EXAMPLE

Large Graph
A ----- B ----- C
|       |
|       |
D ----- E

Query Graph
X ----- Y
|       |
|       |
Z ----- W

Result: Query Graph Exists Inside Larger Graph.

------------------------------------------------------------
WHY SUBGRAPH MATCHING IS IMPORTANT

Applications:
• Pattern Recognition
• Drug Discovery
• Network Analysis
• Fraud Detection

------------------------------------------------------------
COMPLEXITY

Category: NP-Complete
Meaning: Extremely difficult for large graphs.

------------------------------------------------------------
SEARCHING IN GRAPH DATABASES

Graph databases store entire collections of graphs.
Goal: Find all occurrences of a query graph within the database.

------------------------------------------------------------
INPUT

Graph Database:
G1
G2
G3
G4

Query Graph: Q

------------------------------------------------------------
OUTPUT

All graphs containing Q.

------------------------------------------------------------
APPLICATIONS

• Molecular Databases
• Social Networks
• Biological Research
• Knowledge Graphs

------------------------------------------------------------
GRAPH SEARCH CHALLENGES

Problem:
Many possible vertex mappings must be tested.
Large graphs create enormous search spaces.

------------------------------------------------------------
THREE RESEARCH APPROACHES

1. Special Graph Matching

Examples:
• Planar Graphs
• Connected Graphs

Goal: Reduce complexity.

------------------------------------------------------------
2. Reduce Mapping Generation

Goal: Generate fewer candidate matches.
Result: Faster searching.

------------------------------------------------------------
Approximate Matching

Goal: Find near matches rather than exact matches.
Result: Faster execution.

------------------------------------------------------------
APPROXIMATE GRAPH MATCHING

Exact matches may not exist.
Solution: Search for similar graphs instead.

------------------------------------------------------------
EXAMPLE

Graph A
A ----- B
|
|
C

Graph B
A ----- B
|
|
D

Result:
Very Similar Graphs
Match Score: High

------------------------------------------------------------
ADVANTAGES

• Handles noisy data
• Finds similar structures
• Faster than exact matching

------------------------------------------------------------
GRAPH SEARCH COMPLEXITY

Exact Matching: Very Expensive
Subgraph Matching
NP-Complete

Approximate Matching: Faster But not always exact

------------------------------------------------------------
GRAPHGREP

GraphGrep is a graph database search technique.
Purpose: Find all occurrences of a graph pattern within a graph database.

------------------------------------------------------------
WHY GRAPHGREP IS USED

Problem: Graph searching is expensive.
Solution: Create indexes that store graph structure information.

------------------------------------------------------------
HOW GRAPHGREP WORKS

Step 1: Preprocess graph database.
Step 2: Build graph fingerprints.
Step 3: Store structural information.
Step 4: Use fingerprints to reduce searching time.

------------------------------------------------------------
GRAPH FINGERPRINT

A compact representation of graph structure.
Purpose: Quickly eliminate impossible matches.

------------------------------------------------------------
ADVANTAGES OF GRAPHGREP

• Faster searching
• Efficient indexing
• Works with graph databases
• Reduces search space

------------------------------------------------------------
APPLICATIONS OF GRAPHGREP

• Molecular Databases
• Biological Databases
• Web Data
• Network Analysis

SEARCHING IN TREES

Trees are a specialized type of graph.
A hierarchical graph with a root node and no cycles.

------------------------------------------------------------
WHY TREE SEARCHING IS IMPORTANT

Tree structures are widely used in:
• XML Documents
• File Systems
• Digital Libraries
• Family Trees
• Biological Databases

------------------------------------------------------------
TREE SEARCH APPLICATION: COIN DATABASES

Ancient coins can be described using features.

Example:
Coin
│
├── Shape
├── Material
├── Inscription
└── Symbol

Each feature becomes part of a tree structure.

------------------------------------------------------------
PURPOSE

When a new coin is discovered: Search tree database for similar coins.
Result: Determine origin and classification.

------------------------------------------------------------
TREE MATCHING

Tree searching often involves:
• Exact Matching
• Approximate Matching

------------------------------------------------------------
EXACT TREE MATCHING

Goal: Find an identical tree.

Example:
Tree A = Tree B
Result: Match Found

------------------------------------------------------------
APPROXIMATE TREE MATCHING

Goal: Find similar trees.
Used when exact matches do not exist.

------------------------------------------------------------
EXAMPLE

Tree A
Coin
├── Gold
└── Roman

Tree B
Coin
├── Gold
└── Greek

Result: Partial Match
Similarity Score: High

------------------------------------------------------------
TREE SEARCH IN XML

XML documents naturally form trees.

Example:
<Book>

    <Author>
</Book>

------------------------------------------------------------
TREE STRUCTURE

├── Title
└── Author

------------------------------------------------------------
PURPOSE

Search XML databases efficiently.

Depends on:
• Ordered Tree

Complexity ranges from: Polynomial Time (P) to NP-Complete

COMMON TREE SEARCH ALGORITHMS

These tree structures are advanced versions of trees that make searching much faster, 
especially when dealing with large amounts of data such as images, 
locations, online shopping products, or fingerprints.

Think of them as different ways of organizing a huge library so that books can be found faster.

------------------------------------------------------------
1. VP-TREE (VANTAGE POINT TREE)

Idea: Instead of sorting data by value, a VP-Tree sorts data by distance.

------------------------------------------------------------
REAL-LIFE EXAMPLE

Imagine you are at a shopping mall.
You need to find the store most similar to Nike.

Instead of checking every store:
Pick one store as a reference point (called the Vantage Point).
Measure how far every other store is from that point.
Arrange stores based on distance.

------------------------------------------------------------
HOW IT WORKS

Reference Store
       |
   Distance
  /         \
Near      Far

When searching: Want similar shoes?
Search only the "Near" branch.
Ignore the "Far" branch.

------------------------------------------------------------
USES

• Face Recognition
• Image Search
• Music Recommendation
• Similar Product Search
• Fingerprint Matching

------------------------------------------------------------
EXAMPLE

Upload a photo of a dog.
VP-Tree helps Google Images quickly find visually similar dogs 
instead of checking millions of pictures one by one.

------------------------------------------------------------
ADVANTAGE

Very fast for similarity searching.

------------------------------------------------------------
2. MVP-TREE (MULTI VANTAGE POINT TREE)

Idea: Uses MULTIPLE reference points instead of one.

------------------------------------------------------------
REAL-LIFE EXAMPLE

Suppose you are searching for a restaurant in Cyprus.
Using one landmark: "Distance from Nicosia"

Using multiple landmarks:
• Distance from Nicosia
• Distance from Kyrenia
• Distance from Famagusta

works much better.

------------------------------------------------------------
HOW IT WORKS

Reference Point A
Reference Point B
Reference Point C

Every object stores distances to several reference points.

------------------------------------------------------------
RESULT

Search area shrinks much faster.
Less searching needed.

------------------------------------------------------------
USES

• Large Image Databases
• DNA Matching
• Medical Records
• Massive Product Catalogs

------------------------------------------------------------
EXAMPLE

Netflix has millions of movies.
Instead of comparing every movie:

Use multiple characteristics:
• Genre
• Rating
• Popularity
• Viewing History

Movies are grouped faster.

------------------------------------------------------------
ADVANTAGE

Even faster than VP-Tree for huge datasets.

------------------------------------------------------------
3. M-TREE (METRIC TREE)

Idea: Organizes data using distances between objects.
Designed specifically for huge databases.

------------------------------------------------------------
REAL-LIFE EXAMPLE

Imagine Google Maps.
You search: "Restaurants within 5 km"
Google does NOT check every restaurant on Earth.

------------------------------------------------------------
HOW IT WORKS

M-Tree groups nearby objects together.

Nicosia Cluster
    |
Schools
Hospitals
Restaurants

Kyrenia Cluster
    |
Schools
Hospitals
Restaurants

------------------------------------------------------------
SEARCH PROCESS

Want restaurants near Nicosia?
Search only the Nicosia branch.
No need to check Kyrenia or Limassol.

------------------------------------------------------------
USES

• GPS Systems
• Geographic Databases
• Hospitals
• Search Engines
• Machine Learning

------------------------------------------------------------
EXAMPLE

Google Maps
Search: "Coffee shops within 2 km"
M-Tree quickly eliminates distant locations.

------------------------------------------------------------
ADVANTAGE

Very efficient for location-based searches.

------------------------------------------------------------
4. FQ-TREE (FIXED QUERY TREE)

Idea: Optimized when the same type of search is performed repeatedly.

------------------------------------------------------------
REAL-LIFE EXAMPLE

University Database
Students frequently ask: "What courses am I eligible for?"
This question is asked thousands of times.

------------------------------------------------------------
NORMAL SEARCH

Search entire database every time.
Slow.

------------------------------------------------------------
FQ-TREE APPROACH

Prepare answers in advance.
Organize data around common queries.

------------------------------------------------------------
SEARCH PROCESS

Student Query
      |
   FQ-Tree
      |
Immediate Result

------------------------------------------------------------
USES

• Search Engines
• Recommendation Systems
• Frequently Asked Queries
• Online Shopping

------------------------------------------------------------
EXAMPLE

Amazon

Search: "Laptops under $1000"
Thousands of customers search this every day.
FQ-Tree stores information optimized for these repeated searches.

------------------------------------------------------------
ADVANTAGE

Extremely fast when similar searches happen repeatedly.

Best For: Location Search

Example:
Google Maps

FQ-Tree
