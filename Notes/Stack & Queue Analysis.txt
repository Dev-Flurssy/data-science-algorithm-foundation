UNDERSTANDING STACKS

A stack is a linear data structure that follows the Last-In, First-Out (LIFO) principle.
The last element inserted into the stack is the first element removed.

------------------------------------------------------------
STACK

Think of a stack of plates.

Example:
Top
 ↓
[Plate 4]
[Plate 3]
[Plate 2]
[Plate 1]

To remove a plate:
Remove Plate 4 first.

Result: Last plate added → First plate removed

------------------------------------------------------------
LIFO PRINCIPLE

LIFO stands for: Last In, First Out

Meaning:
Last Item Added
        ↓
First Item Removed

Example:
Push A
Push B
Push C

Stack:
Top
 ↓
C
B
A

Pop Operation: Remove C
Result: C is removed first.

------------------------------------------------------------
WHY STACKS ARE NEEDED

Stacks are extremely useful when dealing with temporary data.

Applications:
• Function Calls
• Undo Operations
• Expression Evaluation
• Delimiter Matching
• Browser History
• Recursion

------------------------------------------------------------
REAL-LIFE EXAMPLE 1: MAIL STACK

Suppose letters arrive throughout the day.

Arrival Order:
Letter A
Letter B
Letter C
Letter D

Stack:
Top
 ↓
D
C
B
A

Processing: D → C → B → A
Result: Most recently received letter is processed first.

------------------------------------------------------------
REAL-LIFE EXAMPLE 2: WORK TASKS

Current Task: Project A
Suddenly: Project B becomes urgent

Later: Meeting C starts
Then: Phone Call D arrives

Stack:
Top
 ↓
D
C
B
A

Work Order:
Finish D
Return to C
Return to B
Return to A

This is exactly how stack behavior works.

------------------------------------------------------------
BASIC STACK OPERATIONS

The main stack operations are:
• Push
• Pop
• Peek

------------------------------------------------------------
PUSH OPERATION

Push means adding an item to the top of the stack.

Example:
Before:
Top
 ↓
30
20
10

Push 40

After:
Top
 ↓
40
30
20
10

------------------------------------------------------------
POP OPERATION

Pop means removing the top element from the stack.

Example:
Before:
Top
 ↓
40
30
20
10

Pop

After:
Top
 ↓
30
20
10

Removed:
40

------------------------------------------------------------
PEEK OPERATION

Peek allows us to examine the top element without removing it.

Example:
Stack:
Top
 ↓
40
30
20
10

Peek Result: 40
Stack Remains Unchanged

------------------------------------------------------------
STACK OVERFLOW

Overflow occurs when attempting to push into a full stack.

Example:
Maximum Capacity = 5

Current Stack:
5
4
3
2
1

Push 6
Result: Overflow Error

------------------------------------------------------------
STACK UNDERFLOW

Underflow occurs when attempting to pop from an empty stack.

Example:
Stack: Empty
Attempt: Pop
Result: Underflow Error

------------------------------------------------------------
STACK IMPLEMENTATION

Stacks can be implemented using:
• Arrays
• Linked Lists

------------------------------------------------------------
ARRAY IMPLEMENTATION

Example:
Index   Value
0       10
1       20
2       30

Top = 2

Advantages:
• Simple implementation
• Fast access

Disadvantages:
• Fixed size

------------------------------------------------------------
LINKED LIST IMPLEMENTATION

Each node stores:
• Data
• Reference to next node

Advantages:
• Dynamic size
• No fixed capacity

Disadvantages:
• Extra memory required for pointers

------------------------------------------------------------
STACK TIME COMPLEXITY

Operation        Complexity

Push             O(1)
Pop              O(1)
Peek             O(1)
Search           O(n)

------------------------------------------------------------
WHY STACK OPERATIONS ARE FAST

All operations occur only at the top.
No shifting of elements is required.

------------------------------------------------------------
STACK APPLICATION 1: FUNCTION CALLS

Stacks are heavily used during function execution.

Example:
main()
   ↓
functionA()
   ↓
functionB()

Stack:
Top
 ↓
functionB
functionA
main

When functionB completes: Pop functionB
Return to functionA

------------------------------------------------------------
STACK APPLICATION 2: EXPRESSION EVALUATION

Stacks help evaluate expressions.

Example:
3 × (4 + 5)

Steps:
1. Store operators and parentheses
2. Compute inner expression first
3. Return result

Result: 3 × 9 = 27

------------------------------------------------------------
STACK APPLICATION 3: DELIMITER MATCHING

Stacks help verify matching symbols.

Symbols:
()
[]
{}

------------------------------------------------------------
HOW DELIMITER MATCHING WORKS

Opening Symbols:([{
Action: Push onto Stack

Closing Symbols: )]}
Action: Pop from Stack
Compare

If Matching: Continue
If Not Matching: Error

------------------------------------------------------------

• Simple implementation
• Efficient memory use

------------------------------------------------------------
STACK DISADVANTAGES

STACK VS ARRAY

QUEUES

A queue is a linear data structure that follows the First-In, First-Out (FIFO) principle.
The first element inserted is the first element removed.

------------------------------------------------------------
FIFO PRINCIPLE

FIFO stands for: First In, First Out

Meaning:
First Item Added
        ↓
First Item Removed

------------------------------------------------------------
QUEUE EXAMPLE

Think of a ticket line.
Front                               Rear
[A] [B] [C] [D]

Person A arrives first.
Person A gets served first.

------------------------------------------------------------
STACK VS QUEUE

Stack: LIFO
Last In → First Out

Example:
Pile of Plates

------------------------------------------------------------

Queue:FIFO 
First In → First Out

Example:
Waiting Line

------------------------------------------------------------
WHY QUEUES ARE NEEDED

Queues are useful whenever tasks must be processed in order.

Applications:
• Print Queues
• Task Scheduling
• Keyboard Input Buffers
• Network Packets
• Customer Service Systems

------------------------------------------------------------
REAL-LIFE EXAMPLE

Bank Queue
Front                       Rear
John → Mary → David → Sarah

Service Order:
1. John
2. Mary
3. David
4. Sarah

------------------------------------------------------------
QUEUE OPERATIONS

Main Operations:
• Enqueue
• Dequeue
• Peek

------------------------------------------------------------
ENQUEUE OPERATION

Enqueue means adding an item to the rear of the queue.

Example:
Queue:
Front      Rear
10   20   30
Enqueue 40

Result:
Front           Rear
10   20   30   40

------------------------------------------------------------
DEQUEUE OPERATION

Dequeue means removing an item from the front.

Example:
Queue:
Front           Rear
10   20   30   40
Dequeue

Result:
Front      Rear
20   30   40

Removed: 10

------------------------------------------------------------
PEEK OPERATION

Peek returns the front element without removing it.

Example:
Queue:
Front           Rear
10   20   30   40

Peek Result: 10
Queue Remains Unchanged

------------------------------------------------------------
QUEUE IMPLEMENTATION

Queues can be implemented using:

• Arrays
• Linked Lists

------------------------------------------------------------
ARRAY IMPLEMENTATION

Example:
Index   Value
0       10
1       20
2       30

Advantages:
• Easy implementation

Disadvantages:
• May require fixed size

------------------------------------------------------------
LINKED LIST IMPLEMENTATION

Each node contains:
• Data
• Reference to next node

Advantages:
• Dynamic size
• Flexible memory usage

------------------------------------------------------------
CIRCULAR QUEUE

A circular queue reuses empty spaces created at the beginning of the array.

------------------------------------------------------------
PROBLEM WITH NORMAL ARRAY QUEUE

After several deletions:
Front → moves right
Rear → continues moving right

Eventually:
Rear reaches the last index
Even though empty spaces exist at the front.

------------------------------------------------------------
SOLUTION: CIRCULAR QUEUE

Instead of stopping: Rear wraps around to the beginning.

Example:
Array Size = 5
Index: 0 1 2 3 4
Rear reaches index 4

Next insertion:
Rear returns to index 0

Result: Array space is reused efficiently.

------------------------------------------------------------
QUEUE TIME COMPLEXITY

Operation          Complexity

Enqueue            O(1)
Dequeue            O(1)
Peek               O(1)
Search             O(n)

------------------------------------------------------------
WHY QUEUE OPERATIONS ARE FAST

Insertion occurs only at rear.
Removal occurs only at front.
No shifting is required.

------------------------------------------------------------
ERROR CONDITIONS

QUEUE OVERFLOW
Occurs when attempting to insert into a full queue.

Example:
Capacity = 5
Queue Already Contains 5 Items
Enqueue New Item

Result: Overflow Error

------------------------------------------------------------
QUEUE UNDERFLOW

Occurs when attempting to remove from an empty queue.

Example:
Queue Empty
Dequeue

Result: Underflow Error

PRIORITY QUEUES

A priority queue is a special type of queue where elements are processed according to priority.

------------------------------------------------------------
WHAT IS A PRIORITY QUEUE?

Items are removed based on priority rather than arrival order.
Highest Priority Item → Removed First

------------------------------------------------------------
NORMAL QUEUE

Arrival Order: 10 → 20 → 30 → 40
Removal Order: 10 → 20 → 30 → 40
FIFO

------------------------------------------------------------
PRIORITY QUEUE

Items:
20
5
50
10

Removal Order: 5 → 10 → 20 → 50
Highest Priority Processed First

------------------------------------------------------------
REAL-LIFE EXAMPLE

Hospital Emergency Room

Patients:
Patient A → Minor Injury
Patient B → Heart Attack
Patient C → Fever

Treatment Order:
Patient B
Patient C
Patient A

Reason: Priority, not arrival time.

------------------------------------------------------------
HOW PRIORITY QUEUES WORK

Elements remain sorted based on priority.

Example:
Queue: 50 40 30 20 10
Highest Priority: 10
Removed First

------------------------------------------------------------
PRIORITY QUEUE OPERATIONS

Insertion: Place item in correct sorted position.
Deletion: Remove highest-priority item.
Peek: View highest-priority item.

------------------------------------------------------------
INSERTION IN PRIORITY QUEUE

Example:
Current Queue: 500 400 200 100
Insert: 300
Result: 500 400 300 200 100

------------------------------------------------------------
WHY INSERTION IS SLOWER

To maintain order:
• Search required
• Elements may need shifting

Time Complexity: O(n)

------------------------------------------------------------
DELETION IN PRIORITY QUEUE

Highest-priority item already sits at the front.

Example:
500 400 300 200 100
Delete: 100

Result: 500 400 300 200

------------------------------------------------------------
WHY DELETION IS FAST

Item is already positioned correctly.
No searching required.
Time Complexity: O(1)

------------------------------------------------------------
PRIORITY QUEUE TIME COMPLEXITY

Operation          Complexity
Insertion          O(n)
Deletion           O(1)
Peek               O(1)

------------------------------------------------------------
USES OF PRIORITY QUEUES

• CPU Scheduling
• Task Management
• Emergency Systems
• Dijkstra's Algorithm
• Network Routing
• Event Simulation
