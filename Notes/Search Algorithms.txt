SEARCH ALGORITHMS

Searching is the process of finding a specific item within a collection of data.

Examples:
• Finding a contact in a phonebook
• Searching for a website
• Looking for a student's record
• Finding a product in a database

Purpose:
• Fast information retrieval
• Efficient data processing
• Easy access to required records

------------------------------------------------------------
WHY SEARCHING IS IMPORTANT

Searching helps locate desired information quickly from a large collection of data.

Example:
List: 13 12 18 6 -4 9
Search Key: 6

Result: Element Found
Without searching techniques, locating information manually would be slow and inefficient.

------------------------------------------------------------
SEARCH KEY

A search key is the value used to identify and locate a specific item.

Example:
List: 13 12 18 6 -4 9

Search Key: 6
Here, 6 is the search key.

Properties:
• Identifies the required data item
• Used during comparisons
• May be unique or non-unique depending on the application

------------------------------------------------------------
SEARCH INPUTS

Most search algorithms require:
• Array or Collection (A)
• Number of Elements (n)
• Search Key (x)

Output:
• Position of x if found
• "Not Found" if x does not exist

------------------------------------------------------------
TYPES OF SEARCH ALGORITHMS

1. Unordered Linear Search
2. Ordered Linear Search
3. Chunk Search
4. Binary Search

------------------------------------------------------------
UNORDERED LINEAR SEARCH

Unordered Linear Search is used when data is not sorted.
Search each element one by one from the beginning until the required item is found.

Also Called:
• Linear Search
• Sequential Search
• Serial Search

------------------------------------------------------------
WORKING OF UNORDERED LINEAR SEARCH

Steps:
1. Start from the first element.
2. Compare it with the key.
3. If equal, stop.
4. Otherwise move to the next element.
5. Repeat until the key is found or the list ends.

------------------------------------------------------------
EXAMPLE (KEY FOUND)

Array: [35, 17, 26, 34, 8, 23, 49, 9]
Search: 34

Comparisons:
34 = 35 ? No
34 = 17 ? No
34 = 26 ? No
34 = 34 ? Yes

Result: Position = 4
Comparisons = 4

------------------------------------------------------------
EXAMPLE (KEY NOT FOUND)

Array: [35, 17, 26, 34, 8, 23, 49, 9]
Search: 19

Process:
35
17
26
34
8
23
49
9

Result: 19 Not Found
Comparisons = 8

------------------------------------------------------------
ALGORITHM

1. Start at index 0.
2. Compare current element with key.
3. If match is found, return position.
4. Else move to the next element.
5. Continue until end of list.
6. If key is not found, report unsuccessful search.

------------------------------------------------------------
ADVANTAGES

• Very simple
• Easy to implement
• Works on unsorted data
• No preprocessing required

------------------------------------------------------------
DISADVANTAGES

• Slow for large datasets
• May examine every element
• Less efficient than Binary Search

------------------------------------------------------------
TIME COMPLEXITY

Best Case: O(1)
Average Case: O(n)
Worst Case: O(n)
Formula: T(n) = n

------------------------------------------------------------
ORDERED LINEAR SEARCH

Ordered Linear Search is used when data is already sorted.
Search from left to right and stop immediately when the current value becomes larger than the target value.

------------------------------------------------------------
EXAMPLE

Sorted Array: [8, 9, 17, 23, 26, 34, 35, 49]
Search: 34

Comparisons:
34 > 8
34 > 9
34 > 17
34 > 23
34 > 26
34 = 34

Result: Position = 6

------------------------------------------------------------
EARLY STOPPING EXAMPLE

Search: 19
Array: [8, 9, 17, 23, 26, 34, 35, 49]

Comparisons:
19 > 8
19 > 9
19 > 17
19 < 23

Result: 19 Not Found
Reason: Since 23 is already larger than 19, all remaining elements must also be larger.

------------------------------------------------------------
ADVANTAGE OVER UNORDERED SEARCH

The search can stop early when it becomes impossible for the target to exist in the remaining portion of the array.

------------------------------------------------------------
TIME COMPLEXITY

Best Case: O(1)
Average Case: O(n)
Worst Case: O(n)

Formula: T(n) = 2n

------------------------------------------------------------
CHUNK SEARCH

Chunk Search divides a sorted list into smaller groups called chunks.
Search chunk boundaries first and then perform Linear Search within the selected chunk.

------------------------------------------------------------
WHY CHUNK SEARCH IS USED

Problem: Linear Search examines too many elements.
Solution: Break the data into smaller chunks.

------------------------------------------------------------
EXAMPLE

Array: [8, 9, 17, 23, 26, 34, 35, 49]
Chunk Size: 2

------------------------------------------------------------
CREATE CHUNKS

Chunk 1: [8, 9]
Chunk 2: [17, 23]
Chunk 3: [26, 34]
Chunk 4: [35, 49]

------------------------------------------------------------
SEARCH FOR 34

Check chunk-ending elements:
9
23
34

Correct chunk found.

------------------------------------------------------------
SEARCH INSIDE CHUNK

Chunk: [26, 34]

Search:
26
34
Found

Result: Position = 6

------------------------------------------------------------
ADVANTAGES

• Faster than Linear Search
• Reduces the number of comparisons

------------------------------------------------------------
DISADVANTAGES

• More difficult to implement
• Slower than Binary Search

------------------------------------------------------------
TIME COMPLEXITY

Formula: T(n) = n/c + 2c

Where:
n = Number of Elements
c = Chunk Size

------------------------------------------------------------
BINARY SEARCH

Binary Search is one of the fastest searching techniques.
Binary Search repeatedly divides the search space into two halves until the target is found.

Requirement: The data must be sorted.

------------------------------------------------------------
WHY BINARY SEARCH IS FAST

Instead of checking every element:
Linear Search: 1 → 2 → 3 → 4 → 5 → 6 → 7
Binary Search: Check Middle → Discard Half → Check New Middle → Discard Half Again

Each comparison removes approximately half of the remaining data.

------------------------------------------------------------
CONDITIONS FOR BINARY SEARCH

The list must be: Sorted in Ascending Order OR Sorted in Descending Order
Without sorting, Binary Search cannot work correctly.

------------------------------------------------------------
MIDDLE ELEMENT CALCULATION

Formula: mid = (first + last) // 2

Example:
Array: 2 3 5 7 10 11 12
Indexes: 0 1 2 3 4 5 6

Calculation:
mid = (0 + 6) // 2
mid = 3

Middle Element: 7

------------------------------------------------------------
WORKING OF BINARY SEARCH

Three possible outcomes:
Middle = Key
Search Successful

Middle > Key
Search Left Half

Middle < Key
Search Right Half

------------------------------------------------------------
EXAMPLE (KEY FOUND)

Sorted List: 2 3 5 7 10 11 12
Search Key: 10

------------------------------------------------------------
ITERATION 1

first = 0
last = 6
mid = 3

Element = 7
10 > 7

Search Right Half
first = 4

------------------------------------------------------------
ITERATION 2

first = 4
last = 6
mid = 5

Element = 11
10 < 11

Search Left Half
last = 4

------------------------------------------------------------
ITERATION 3

first = 4
last = 4

mid = 4
Element = 10

Found

Result:
Position = 5
Index = 4

------------------------------------------------------------
EXAMPLE (KEY NOT FOUND)

Array: [8, 9, 17, 23, 26, 34, 35, 49]

Search: 30

Process:
Middle = 23
Search Right

Middle = 34
Search Left

Middle = 26
Search Right

No elements remain.
Result: 30 Not Found

------------------------------------------------------------
ALGORITHM

1. Set first = 0.
2. Set last = n − 1.
3. Find the middle element.
4. Compare middle element with key.
5. If equal, return position.
6. If key is smaller, search left half.
7. If key is larger, search right half.
8. Continue until key is found or search space becomes empty.

------------------------------------------------------------
ADVANTAGES

• Extremely fast
• Reduces search space rapidly
• Efficient for large datasets
• Requires very few comparisons

------------------------------------------------------------
DISADVANTAGES

• Data must be sorted
• More complex than Linear Search
• Sorting may add extra overhead

------------------------------------------------------------
TIME COMPLEXITY

Best Case: O(1)
Average Case: O(log n)

Worst Case: O(log n)
Formula: T(n) = 2log₂(n)

------------------------------------------------------------
WHY BINARY SEARCH IS BETTER

Array Size = 1,000
Linear Search: Up to 1,000 comparisons
Binary Search: About 10 comparisons

Array Size = 1,000,000
Linear Search: Up to 1,000,000 comparisons
Binary Search: About 20 comparisons

------------------------------------------------------------
COMPARISON OF SEARCH ALGORITHMS

Algorithm                Time Complexity
Unordered Linear Search  O(n)
Ordered Linear Search    O(n)
Chunk Search             O(n/c + 2c)
Binary Search            O(log n)

------------------------------------------------------------
WHEN TO USE EACH SEARCH

UNORDERED LINEAR SEARCH

Use When:
• Data is unsorted
• Data size is small
• Simplicity is required

------------------------------------------------------------
ORDERED LINEAR SEARCH

Use When:
• Data is sorted
• Dataset is relatively small

------------------------------------------------------------
CHUNK SEARCH

Use When:
• Data is sorted
• Dataset is medium-sized
• Fewer comparisons are desired

------------------------------------------------------------
BINARY SEARCH

Use When:
• Data is sorted
• Dataset is large
• Fast searching is required

------------------------------------------------------------
LINEAR SEARCH VS BINARY SEARCH

Linear Search

• Works on sorted or unsorted data
• Sequential checking
• No sorting required
• Time Complexity = O(n)

Binary Search
• Works only on sorted data
• Divide-and-conquer approach
• Much faster for large datasets
• Time Complexity = O(log n)
