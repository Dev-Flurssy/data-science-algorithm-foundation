SEARCH ALGORITHMS

A search algorithm is a method used to locate a specific item within a collection of data.

------------------------------------------------------------
WHY SEARCH ALGORITHMS ARE NEEDED

Searching is one of the most common operations in computer science.

Examples:
• Finding a contact in a phone book
• Searching a student record
• Looking up a product ID
• Retrieving customer information

Problem:
Large datasets make manual searching inefficient.

Solution:
Search algorithms help locate data quickly and efficiently.

------------------------------------------------------------
SEARCH INPUTS

Most search algorithms require:
• Array or Collection (A)
• Number of Elements (n)
• Search Key (x)

Output:
• Position of x if found
• "Not Found" if x does not exist

------------------------------------------------------------
TYPES OF SEARCH ALGORITHMS

1. Unordered Linear Search
2. Ordered Linear Search
3. Chunk Search
4. Binary Search

------------------------------------------------------------
UNORDERED LINEAR SEARCH

Unordered Linear Search is used when data is not sorted.
Search each element one by one from the beginning until the item is found.

------------------------------------------------------------
EXAMPLE

Array: [35, 17, 26, 34, 8, 23, 49, 9]
Search: 34

------------------------------------------------------------
STEPS

Compare 34 with 35: Not Found
Compare 34 with 17: Not Found
Compare 34 with 26: Not Found
Compare 34 with 34: Found

------------------------------------------------------------
RESULT

Position = 4
Comparisons = 4

------------------------------------------------------------
ELEMENT NOT FOUND

Search: 19
Array: [35, 17, 26, 34, 8, 23, 49, 9]

Process: Compare every element
35
17
26
34
8
23
49
9

Result: 19 Not Found
Comparisons = 8

------------------------------------------------------------
TIME COMPLEXITY

Worst Case: O(n)
Formula: T(n) = n

------------------------------------------------------------
CHARACTERISTICS

Advantages:
• Very simple
• Works on any data

Disadvantages:
• Slow for large datasets

------------------------------------------------------------
 ORDERED LINEAR SEARCH

Ordered Linear Search is used when data is already sorted.

Definition:
Search from left to right but stop early when the current value becomes larger than the target.

------------------------------------------------------------
EXAMPLE

Sorted Array: [8, 9, 17, 23, 26, 34, 35, 49]
Search: 34

------------------------------------------------------------
STEPS

34 > 8: Continue
34 > 9: Continue
34 > 17: Continue
34 > 23: Continue
34 > 26: Continue
34 = 34: Found

------------------------------------------------------------
RESULT

Position = 6

------------------------------------------------------------
EARLY STOPPING EXAMPLE

Search: 19
Array: [8, 9, 17, 23, 26, 34, 35, 49]

------------------------------------------------------------
STEPS

19 > 8: Continue
19 > 9: Continue
19 > 17: Continue
19 < 23: Stop Search

------------------------------------------------------------
RESULT

19 Not Found
Reason: All remaining elements are larger than 19.

------------------------------------------------------------
TIME COMPLEXITY

Worst Case: O(n)
Formula: T(n) = 2n

------------------------------------------------------------
ADVANTAGE OVER UNORDERED SEARCH

Can stop earlier when the target cannot exist.

------------------------------------------------------------
CHUNK SEARCH

Chunk Search divides an ordered list into smaller groups called chunks.
Search chunk boundaries first, then perform linear search inside the selected chunk.

------------------------------------------------------------
WHY CHUNK SEARCH IS USED

Problem: Linear Search examines too many elements.
Solution: Divide data into manageable chunks.

------------------------------------------------------------
EXAMPLE

Array: [8, 9, 17, 23, 26, 34, 35, 49]
Chunk Size = 2

------------------------------------------------------------
CHUNKS

Chunk 1: [8, 9]
Chunk 2: [17, 23]
Chunk 3: [26, 34]
Chunk 4: [35, 49]

------------------------------------------------------------
SEARCH FOR 34

Check Last Elements:
9
23 
34

Found correct chunk

------------------------------------------------------------
PERFORM LINEAR SEARCH

Chunk: [26, 34]
Search:
26
34
Found

------------------------------------------------------------
RESULT

Position = 6

------------------------------------------------------------
TIME COMPLEXITY

Formula: T(n) = n/c + 2c

Where:
n = Number of Elements
c = Chunk Size

------------------------------------------------------------
ADVANTAGES

• Faster than ordinary linear search
• Fewer comparisons

------------------------------------------------------------
DISADVANTAGES

• More complex implementation
• Still slower than binary search

------------------------------------------------------------
BINARY SEARCH

Binary Search is an efficient algorithm that repeatedly divides the search space into two halves.
Search by repeatedly eliminating half the remaining data.

Requirement: Data must be sorted.

------------------------------------------------------------
WHY BINARY SEARCH IS FAST

Each comparison removes half of the remaining elements.

------------------------------------------------------------
EXAMPLE

Array: [8, 9, 17, 23, 26, 34, 35, 49]
Search: 26

------------------------------------------------------------
STEPS

Middle Element: 23
26 > 23
Search Right Half
Remaining: [26, 34, 35, 49]

Middle Element:
34
26 < 34
Search Left Half
Remaining: [26]

26 = 26
Found

------------------------------------------------------------
RESULT

Position = 5

------------------------------------------------------------
ELEMENT NOT FOUND

Search: 30
Array: [8, 9, 17, 23, 26, 34, 35, 49]

------------------------------------------------------------
STEP S

Middle: 23
Search Right

Middle: 34
Search Left

26
Search Right

------------------------------------------------------------
NO ELEMENTS REMAIN

Result: 30 Not Found

------------------------------------------------------------
TIME COMPLEXITY

Worst Case: O(log n)
Formula: T(n) = 2log₂(n)

------------------------------------------------------------
WHY BINARY SEARCH IS BETTER

Array Size = 1,000
Linear Search: Up to 1,000 comparisons
Binary Search: About 10 comparisons

------------------------------------------------------------
ARRAY SIZE = 1,000,000

Linear Search: Up to 1,000,000 comparisons
Binary Search: About 20 comparisons

------------------------------------------------------------
COMPARISON OF SEARCH ALGORITHMS

Algorithm               Time Complexity

Unordered Linear Search     O(n)
Ordered Linear Search       O(n)
Chunk Search                O(n/c + 2c)
Binary Search               O(log n)

------------------------------------------------------------
WHEN TO USE EACH SEARCH

Unordered Linear Search
Use When: 
•Data is unsorted

Ordered Linear Search
Use When:
• Data is sorted
• Dataset is small

Chunk Search

Use When:
• Ordered data
• Medium-sized datasets

Binary Search
Use When:
• Data is sorted
• Fast searching is required

------------------------------------------------------------
ADVANTAGES OF BINARY SEARCH

• Extremely fast
• Reduces search space quickly
• Efficient for large datasets

------------------------------------------------------------
DISADVANTAGES OF BINARY SEARCH

• Requires sorted data
• More complex than linear search

SEARCHING IN GRAPHS

Graphs are powerful data structures used to represent relationships between data.
A graph consists of vertices (nodes) connected by edges.

------------------------------------------------------------
WHY GRAPHS ARE USED

Graphs are used whenever relationships between objects need to be represented.

Examples:
• Social Networks
• Road Maps
• Biological Databases
• Web Pages
• Computer Networks
• Recommendation Systems

------------------------------------------------------------
GRAPH STRUCTURE

Example:
      A
     / \
    B---C
     \
      D

Vertices: A, B, C, D
Edges: AB, AC, BC, BD

------------------------------------------------------------
GRAPH COMPONENTS

Vertex (Node) → Represents an object or data item
Edge → Represents the relationship between objects

------------------------------------------------------------
WHY SEARCHING IN GRAPHS IS IMPORTANT

Graph searching helps answer questions such as:
• Are two graphs identical?
• Does a graph contain a certain pattern?
• Does a graph contain a smaller graph?
• Are two structures similar?

------------------------------------------------------------
REAL-WORLD APPLICATIONS

Biological Databases
Vertices: Atoms
Edges: Chemical Bonds
Purpose: Compare molecular structures.

Web Search Engines
Vertices: Web Pages
Edges: Hyperlinks
Purpose: Determine page relevance.

Computer Vision
Vertices: Image Regions
Edges: Relationships between regions
Purpose: Pattern recognition.

Network Systems
Vertices: Computers
Edges: Connections
Purpose:Route discovery and analysis.

------------------------------------------------------------
EXACT MATCH (GRAPH ISOMORPHISM)

Graph Isomorphism determines whether two graphs are structurally identical.
Two graphs are isomorphic if their vertices and edges can be matched exactly.

------------------------------------------------------------
EXAMPLE

Graph 1
A ----- B
|       |
|       |
C ----- D

Graph 2
P ----- Q
|       |
|       |
R ----- S

Observation
A ↔ P
B ↔ Q
C ↔ R
D ↔ S

Both graphs have identical structures.
Result: Graphs Are Isomorphic

------------------------------------------------------------
PURPOSE OF GRAPH ISOMORPHISM

Used to identify:
• Similar network structures
• Similar molecules
• Similar visual objects

------------------------------------------------------------
COMPLEXITY

Very difficult problem.
Category: NP Problem

------------------------------------------------------------
SUBGRAPH EXACT MATCHING: (SUBGRAPH ISOMORPHISM)

Determine whether a smaller graph exists inside a larger graph.

------------------------------------------------------------
EXAMPLE

Large Graph
A ----- B ----- C
|       |
|       |
D ----- E

Query Graph
X ----- Y
|       |
|       |
Z ----- W

Result
Query Graph Exists Inside Larger Graph.

------------------------------------------------------------
WHY SUBGRAPH MATCHING IS IMPORTANT

Applications:
• Pattern Recognition
• Drug Discovery
• Network Analysis
• Fraud Detection

------------------------------------------------------------
COMPLEXITY

Category: NP-Complete
Meaning: Extremely difficult for large graphs.

------------------------------------------------------------
SEARCHING IN GRAPH DATABASES

Graph databases store entire collections of graphs.
Goal: Find all occurrences of a query graph within the database.

------------------------------------------------------------
INPUT

Graph Database:
G1
G2
G3
G4

Query Graph: Q

------------------------------------------------------------
OUTPUT

All graphs containing Q.

------------------------------------------------------------
APPLICATIONS

• Molecular Databases
• Social Networks
• Biological Research
• Knowledge Graphs

------------------------------------------------------------
GRAPH SEARCH CHALLENGES

Problem:
Many possible vertex mappings must be tested.
Large graphs create enormous search spaces.

------------------------------------------------------------
THREE RESEARCH APPROACHES

1. Special Graph Matching

Examples:
• Planar Graphs
• Connected Graphs

Goal: Reduce complexity.

------------------------------------------------------------
2. Reduce Mapping Generation

Goal: Generate fewer candidate matches.
Result: Faster searching.

------------------------------------------------------------
Approximate Matching

Goal: Find near matches rather than exact matches.
Result: Faster execution.

------------------------------------------------------------
APPROXIMATE GRAPH MATCHING

Exact matches may not exist.
Solution: Search for similar graphs instead.

------------------------------------------------------------
EXAMPLE

Graph A
A ----- B
|
|
C

Graph B
A ----- B
|
|
D

Result:
Very Similar Graphs
Match Score: High

------------------------------------------------------------
ADVANTAGES

• Handles noisy data
• Finds similar structures
• Faster than exact matching

------------------------------------------------------------
GRAPH SEARCH COMPLEXITY

Exact Matching: Very Expensive
Subgraph Matching
NP-Complete

Approximate Matching: Faster But not always exact

------------------------------------------------------------
GRAPHGREP

GraphGrep is a graph database search technique.
Purpose: Find all occurrences of a graph pattern within a graph database.

------------------------------------------------------------
WHY GRAPHGREP IS USED

Problem: Graph searching is expensive.
Solution: Create indexes that store graph structure information.

------------------------------------------------------------
HOW GRAPHGREP WORKS

Step 1: Preprocess graph database.
Step 2: Build graph fingerprints.
Step 3: Store structural information.
Step 4: Use fingerprints to reduce searching time.

------------------------------------------------------------
GRAPH FINGERPRINT

A compact representation of graph structure.
Purpose: Quickly eliminate impossible matches.

------------------------------------------------------------
ADVANTAGES OF GRAPHGREP

• Faster searching
• Efficient indexing
• Works with graph databases
• Reduces search space

------------------------------------------------------------
APPLICATIONS OF GRAPHGREP

• Molecular Databases
• Biological Databases
• Web Data
• Network Analysis

SEARCHING IN TREES

Trees are a specialized type of graph.
A hierarchical graph with a root node and no cycles.

------------------------------------------------------------
WHY TREE SEARCHING IS IMPORTANT

Tree structures are widely used in:
• XML Documents
• File Systems
• Digital Libraries
• Family Trees
• Biological Databases

------------------------------------------------------------
TREE SEARCH APPLICATION: COIN DATABASES

Ancient coins can be described using features.

Example:
Coin
│
├── Shape
├── Material
├── Inscription
└── Symbol

Each feature becomes part of a tree structure.

------------------------------------------------------------
PURPOSE

When a new coin is discovered: Search tree database for similar coins.
Result: Determine origin and classification.

------------------------------------------------------------
TREE MATCHING

Tree searching often involves:
• Exact Matching
• Approximate Matching

------------------------------------------------------------
EXACT TREE MATCHING

Goal: Find an identical tree.

Example:
Tree A = Tree B
Result: Match Found

------------------------------------------------------------
APPROXIMATE TREE MATCHING

Goal: Find similar trees.
Used when exact matches do not exist.

------------------------------------------------------------
EXAMPLE

Tree A
Coin
├── Gold
└── Roman

Tree B
Coin
├── Gold
└── Greek

Result: Partial Match
Similarity Score: High

------------------------------------------------------------
TREE SEARCH IN XML

XML documents naturally form trees.

Example:
<Book>
    <Title>
    <Author>
</Book>

------------------------------------------------------------
TREE STRUCTURE

Book
├── Title
└── Author

------------------------------------------------------------
PURPOSE

Search XML databases efficiently.

------------------------------------------------------------
TREE SEARCH COMPLEXITY

Depends on:
• Ordered Tree
• Unordered Tree
• Exact Matching
• Approximate Matching

------------------------------------------------------------
RESULT

Complexity ranges from: Polynomial Time (P) to NP-Complete

------------------------------------------------------------
COMMON TREE SEARCH ALGORITHMS

• FQ-Tree
• VP-Tree
• MVP-Tree
• M-Tree

Purpose: Improve tree-search efficiency.
