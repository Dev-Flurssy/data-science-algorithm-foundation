QUEUE IMPLEMENTATION USING A FIXED-SIZE LIST

In this implementation, the queue has a maximum size.

Meaning:
• Only a limited number of elements can be stored.
• New elements cannot be inserted when the queue becomes full.
• A new operation called isFull() is introduced.

------------------------------------------------------------
FIXED SIZE QUEUE

A fixed-size queue has a predefined capacity.

Example:
Queue Size = 5
Maximum Elements = 5

Meaning:
• Only 5 elements can be stored.
• The 6th insertion causes Overflow.

------------------------------------------------------------
ISFULL OPERATION

isFull(rear, front, size)
Purpose: Checks whether the queue is full.

Condition:
rear >= size - 1

Returns:
1 → Queue is Full
0 → Queue is Not Full

Meaning:
When rear reaches the last position, no more elements can be inserted.

------------------------------------------------------------
EXAMPLE OF ISFULL()

Queue Size = 5
Indexes: 0 1 2 3 4

Queue: [10, 20, 30, 40, 50]

Front = 0
Rear = 4

Condition:
rear >= size - 1
4 >= 4

Result:
Queue is Full

------------------------------------------------------------
QUEUE FULL CONDITION

Queue:
FRONT → 10 20 30 40 50 ← REAR
Size = 5

Meaning:
• Maximum capacity reached.
• No new element can be inserted.

------------------------------------------------------------
ENQUEUE OPERATION (FIXED SIZE QUEUE)

Function:
enqueue(Q, rear, front, size)
Purpose: Inserts an element into the queue.

Before inserting:
Queue fullness is checked.

------------------------------------------------------------
STEPS OF ENQUEUE

1. Check if queue is full.

2. If queue is full:
   Display Overflow message.

3. Otherwise:
   Increment rear by one.
   Insert element at rear.
   Return queue.

------------------------------------------------------------
ENQUEUE EXAMPLE

Queue:
FRONT → 10 20 ← REAR
Rear = 1
Insert 30

After Insertion:
FRONT → 10 20 30 ← REAR
Rear = 2

Meaning:
• Rear moves forward.
• New element joins at the rear.

------------------------------------------------------------
QUEUE OVERFLOW

Overflow occurs when insertion is attempted in a full queue.

Example:
Size = 3

Queue:
FRONT → 10 20 30 ← REAR
Enqueue(40)

Result:
Overflow:
No more place for the Queue

Meaning:
• Queue has reached maximum capacity.
• 40 cannot be inserted.

------------------------------------------------------------
DEQUEUE OPERATION

No change from the previous implementation.
Purpose: Removes the front element.

Meaning:
• Element leaves from the front.
• Front moves forward.
• Queue follows FIFO.

------------------------------------------------------------
ISEMPTY OPERATION

No change from the previous implementation.

Condition:
front > rear
OR
rear == -1

Meaning:
No element exists in the queue.

------------------------------------------------------------
CREATE OPERATION

No change from the previous implementation.

Initial Values:
Q = []
Front = 0
Rear = -1

Meaning:
Queue starts empty.

------------------------------------------------------------
DISPLAY OPERATION

display(Q, front, rear)
Purpose: Displays queue elements.

The function first checks:
1. Is queue empty?
2. Is queue full?
3. Otherwise display queue normally.

------------------------------------------------------------
DISPLAY WHEN QUEUE IS EMPTY

isEmpty(front, rear) == 1
Output: Queue is Empty

Meaning:
No element exists in the queue.

------------------------------------------------------------
DISPLAY WHEN QUEUE IS FULL

isFull(rear, front, size) == 1

Example:
Queue: 10 20 30 40 50

Output:
0 -> 10
1 -> 20
2 -> 30
3 -> 40
4 -> 50

Queue is Full

Meaning:
• Queue contents are displayed.
• Queue capacity has been reached.

------------------------------------------------------------
DISPLAY WHEN QUEUE IS NEITHER FULL NOR EMPTY

Example:
Queue:
[10, 20, 30]

Front = 0
Rear = 2

Output:
0 -> 10
1 -> 20
2 -> 30

Meaning:
Elements are displayed from front to rear.

------------------------------------------------------------
MENU OPERATION
No change from the previous implementation.

------------------------------------------------------------
FIXED-SIZE QUEUE VS DYNAMIC QUEUE

Dynamic Queue
• No fixed size.
• Uses Python list.
• Overflow usually does not occur.

Fixed-Size Queue
• Maximum size is defined.
• isFull() is required.
• Overflow can occur.

------------------------------------------------------------
QUEUE IMPLEMENTATION USING A DICTIONARY

A queue can also be implemented using a dictionary.

Meaning:
• Elements are stored as key-value pairs.
• Keys represent positions (indexes).
• Values represent queue elements.
• Queue size is fixed.

------------------------------------------------------------
DICTIONARY QUEUE REPRESENTATION

A dictionary stores data as:

Key : Value

Example:

Q = {
     0 : 10,
     1 : 15,
     2 : 20
    }

Meaning:
• Key 0 stores 10.
• Key 1 stores 15.
• Key 2 stores 20.

Queue:

FRONT → 10 15 20 ← REAR

------------------------------------------------------------
CREATE OPERATION

Function:

create()

Purpose:
Creates an empty queue.

Initialization:

Q = {}
front = 0
rear = -1

Meaning:
• {} represents an empty dictionary.
• front points to the first element.
• rear = -1 indicates queue is empty.

------------------------------------------------------------
EMPTY QUEUE

Q = {}

Rear = -1

Meaning:
No element exists in the queue.

------------------------------------------------------------

ENQUEUE OPERATION

Function:

enqueue(Q, front, rear, size)

Purpose:
Inserts an element into the queue.

------------------------------------------------------------
STEPS OF ENQUEUE

1. Check whether queue is full.

2. If queue is full:
   Display Overflow message.

3. Otherwise:
   Increment rear by one.
   Store data at Q[rear].
   Return queue and rear.

------------------------------------------------------------
ENQUEUE EXAMPLE

Initial Queue:

Q = {}

Front = 0
Rear = -1

Insert 10

After Insertion:

Q = {
      0 : 10
    }

Front = 0
Rear = 0

------------------------------------------------------------

Insert 15

After Insertion:

Q = {
      0 : 10,
      1 : 15
    }

Front = 0
Rear = 1

Queue:

FRONT → 10 15 ← REAR

Meaning:
Elements are added at the rear.

------------------------------------------------------------
QUEUE OVERFLOW

Overflow occurs when insertion is attempted in a full queue.

Example:

Size = 3

Queue:

{
 0:10,
 1:20,
 2:30
}

Insert 40

Result:

Overflow:
No more place in the Queue

Meaning:
Maximum capacity reached.

------------------------------------------------------------
DEQUEUE OPERATION

Function:

dequeue(Q, front, rear)

Purpose:
Deletes an element from the front of the queue.

------------------------------------------------------------
STEPS OF DEQUEUE

1. Check whether queue is empty.

2. If queue is empty:
   Display Underflow message.

3. Otherwise:
   Delete front element.
   Increment front by one.
   Return queue and front.

------------------------------------------------------------
DEQUEUE EXAMPLE

Queue:

{
 0:10,
 1:15,
 2:20
}

Front = 0
Rear = 2

Delete Front Element

Deleted Element = 10

After Deletion:

{
 1:15,
 2:20
}

Front = 1
Rear = 2

Queue:

FRONT → 15 20 ← REAR

Meaning:
First inserted element leaves first.

------------------------------------------------------------
QUEUE UNDERFLOW

Underflow occurs when deletion is attempted from an empty queue.

Example:

Q = {}

Front = 0
Rear = -1

Delete()

Result:

Underflow:
There is no element in the Queue

Meaning:
No element exists for deletion.

DICTIONARY QUEUE VS LIST QUEUE

LIST QUEUE

• Elements stored in a list.
• Accessed using indexes.
• Simpler implementation.

------------------------------------------------------------

DICTIONARY QUEUE

• Elements stored as key-value pairs.
• Keys act as indexes.
• Values store queue data.
• More flexible storage structure.

------------------------------------------------------------
IMPORTANT POINTS

• Queue is implemented using a dictionary.
• Dictionary stores data as key-value pairs.
• front points to first element.
• rear points to last element.
• Enqueue inserts at rear.
• Dequeue removes from front.
• Queue follows FIFO.
• isFull() checks fullness.
• isEmpty() checks emptiness.
• Overflow occurs when queue is full.
• Underflow occurs when queue is empty.
