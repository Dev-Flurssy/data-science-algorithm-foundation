BASIC TERMINOLOGIES

Basic terminologies are fundamental concepts used in data structures and data management.

------------------------------------------------------------
DATA

Data is a value or a collection of values.

Examples:
• Name
• Age
• Student Marks

Purpose: Represents raw facts and information.

------------------------------------------------------------
DATA ITEM

A data item is a single, distinct element of data.

Examples:
• Student Name
• Employee ID
• Product Price

Properties:
• Represents one unit of information.
• Can be processed independently.

------------------------------------------------------------
GROUP ITEM

A group item consists of multiple related data items.

Example:
Student
• Name
• ID
• Grade

Properties:
• Can be divided into smaller data items.
• Represents related information as a whole.

------------------------------------------------------------
ELEMENTARY ITEM

An elementary item is a data element that cannot be further divided.

Examples:
• Age = 20
• Grade = A

Properties:
• Smallest meaningful data unit.
• Non-splittable.

------------------------------------------------------------
ENTITY AND ATTRIBUTE

An entity is an object about which data is stored.
An attribute is a characteristic or property of an entity.

Example:
Entity: Student

Attributes:
• Student ID
• Age
• Department

Properties:
• Entities represent real-world objects.
• Attributes describe entities.

------------------------------------------------------------
ENTITY SET

An entity set is a collection of similar entities sharing common attributes.

Example:
Students
• Student 1
• Student 2
• Student 3

Common Attributes:
• ID
• Name
• Age

Properties:
• Groups related entities together.
• Commonly used in databases.

------------------------------------------------------------
FIELD

A field is a single unit of information representing one attribute of an entity.

Example:
Student Record
• Name = John
• Age = 21

Properties:
• Stores one specific piece of information.
• Smallest component of a record.

------------------------------------------------------------
RECORD

A record is a collection of related fields describing a single entity.

Example:
Student Record
• ID = 1001
• Name = John
• Department = Computer Science

Properties:
• Represents one complete entity.
• Contains multiple fields.

------------------------------------------------------------
FILE

A file is a collection of records belonging to a particular entity set.

Example:
Student File
• Record 1
• Record 2
• Record 3

Properties:
• Stores multiple records.
• Used for long-term data storage.

------------------------------------------------------------
OVERVIEW OF DATA STRUCTURES

A data structure is a specialized format for organizing, processing, retrieving, and storing data.

------------------------------------------------------------
WHY DATA STRUCTURES ARE NEEDED

Data structures help organize data efficiently and improve program performance.

Benefits:
• Faster Searching
• Faster Insertion
• Faster Deletion
• Better Memory Management

Problem: Simple variables cannot efficiently manage large amounts of interconnected data.
Solution: Data structures provide organized and efficient ways to store, access, and manipulate data.

------------------------------------------------------------
ARRAY

An array stores elements in contiguous memory locations.

Advantages:
• Quick insertion and access if the index is known

Disadvantages:
• Slow deletion
• Slow searching
• Fixed size

------------------------------------------------------------
ORDERED ARRAY

An ordered array stores elements in sorted order.

Advantages:
• Faster searching than an unsorted array

Disadvantages:
• Fixed size
• Slow insertion
• Slow deletion

------------------------------------------------------------
STACK

A stack follows the Last-In, First-Out (LIFO) principle.
The last element inserted is the first element removed.

Example:
Top
↓
30
20
10

Advantages:
• Fast insertion
• Fast deletion

Disadvantages:
• Slow access to other elements

------------------------------------------------------------
QUEUE

A queue follows the First-In, First-Out (FIFO) principle.
The first element inserted is the first element removed.

Example:
Front → 10 | 20 | 30 ← Rear

Advantages:
• Ordered processing
• Easy scheduling of tasks

Disadvantages:
• Slow access to other elements

------------------------------------------------------------
LINKED LIST

A linked list stores elements as connected nodes.

Example:
10 → 20 → 30 → NULL

Advantages:
• Quick insertion
• Quick deletion

Disadvantages:
• Slow searching

------------------------------------------------------------
BINARY TREE

A binary tree is a hierarchical structure where each node has at most two children.

Example:
        50
       /  \
     30    70
    / \    / \
   20 40 60 80

Advantages:
• Fast insertion
• Fast searching
• Fast deletion when balanced

Disadvantages:
• Complex deletion algorithms
• Performance decreases when unbalanced

------------------------------------------------------------
HASH TABLE

A hash table stores data using key-value pairs.

Example:
1001 → John
1002 → Sarah
1003 → David

Advantages:
• Fast access when the key is known
• Quick insertion

Disadvantages:
• Slow deletion
• Inefficient memory usage
• Slow access if the key is unknown

------------------------------------------------------------
HEAP

A heap is a specialized tree used for priority-based operations.
The largest element is always at the root.

Example (Max Heap):
       100
      /   \
    80     70
   / \    /
 50  40  30

Advantages:
• Quick insertion
• Fast access to the largest item
• Quick deletion

Disadvantages:
• Slow access to other elements

------------------------------------------------------------
ANALYZING DATA STRUCTURES AND ALGORITHMS

Analyzing data structures and algorithms helps determine the resources required to solve a problem efficiently.

------------------------------------------------------------
WHY ALGORITHM ANALYSIS IS NEEDED

Algorithm analysis helps compare different solutions and identify the most efficient one.

Resources Measured:
• Computation Time
• Memory Usage
• Hardware Resources
• Communication Bandwidth

Purpose:
• Compare competing algorithms
• Select the most efficient solution
• Eliminate weaker approaches

------------------------------------------------------------
COMPUTATION TIME

Computation time is the amount of time required for an algorithm to produce a result.

Properties:
• Most common measure of performance
• Depends on input size
• Used to compare algorithms

------------------------------------------------------------
RAM MODEL (RANDOM ACCESS MACHINE)

The RAM model is a simplified theoretical model used to analyze algorithms.

Assumptions:
• One processor is used
• Instructions execute one at a time
• Each instruction takes constant time

Common Operations:
• Load
• Store
• Copy
• Addition
• Subtraction
• Multiplication
• Division
• Branching

Purpose:
• Provides a standard way to analyze algorithms
• Makes performance comparisons easier

------------------------------------------------------------
ALGORITHMS LIKE A TECHNOLOGY

Algorithms are considered a fundamental technology because they help computers solve problems efficiently using available resources.

------------------------------------------------------------
WHAT IS AN ALGORITHM?

An algorithm is a step-by-step procedure used to solve a problem or perform a task.

Purpose:
• Produce correct results
• Use resources efficiently
• Complete tasks within a reasonable time

------------------------------------------------------------
WHY ALGORITHMS ARE IMPORTANT

Even if computers become faster, efficient algorithms remain necessary.
Reason: Computer resources are limited.

Limited Resources:
• Processing Time
• Memory
• Storage
• Power Consumption

Solution: Use efficient algorithms to maximize performance.

------------------------------------------------------------
ALGORITHMS VS HARDWARE

System performance depends on both:
• Fast Hardware
• Efficient Algorithms

Example:
Fast Computer + Poor Algorithm
= Poor Performance

Slow Computer + Efficient Algorithm
= Better Performance

------------------------------------------------------------
ALGORITHM EFFICIENCY

The efficiency of an algorithm depends on the amount of resources it consumes.

Main Factors:
• Running Time
• Memory Usage

Goal:
• Achieve maximum performance using minimum resources

------------------------------------------------------------
ADA LOVELACE

Ada Lovelace is widely regarded as the world's first computer programmer.

Contribution:
• Wrote the first computer algorithm.
• Recognized the potential of programmable machines.

------------------------------------------------------------
RANDOMIZED ALGORITHMS

A randomized algorithm uses random choices during execution.

Benefits:
• Often improves average performance
• Useful when worst-case analysis is difficult

Examples:
• Randomized Quick Sort
• Monte Carlo Algorithms

------------------------------------------------------------
INSERTION SORT

Insertion Sort builds a sorted array one element at a time.
Running Time: O(n²)

Characteristics:
• Simple to implement
• Good for small datasets
• Inefficient for large datasets

------------------------------------------------------------
MERGE SORT

Merge Sort divides data into smaller parts and then merges them in sorted order.
Running Time: O(n log n)

Characteristics:
• Efficient for large datasets
• Faster growth rate than Insertion Sort
• Uses extra memory

------------------------------------------------------------
COMPARISON

Insertion Sort: O(n²)
Merge Sort: O(n log n)

Observation:
As the input size increases, Merge Sort becomes significantly faster than Insertion Sort.

------------------------------------------------------------
REAL-WORLD EXAMPLE

Suppose two computers are sorting 10 million numbers.

Computer A:
• Extremely fast hardware
• Uses Insertion Sort

Computer B:
• Slower hardware
• Uses Merge Sort

Result: Computer B may finish significantly faster because Merge Sort is more efficient.
Lesson: Algorithm efficiency often matters more than hardware speed.

------------------------------------------------------------
HARD PROBLEMS

Some computational problems are extremely difficult to solve efficiently, even with modern computers.

------------------------------------------------------------
NON-DETERMINISTIC POLYNOMIAL TIME (NP)

NP refers to a class of problems for which finding a solution is difficult, but verifying a solution is relatively easy.

Properties:
• Solutions are difficult to compute.
• Solutions can be checked efficiently.
• Many important real-world problems belong to this category.

------------------------------------------------------------
NP-COMPLETE PROBLEMS

NP-Complete problems are considered some of the hardest computational problems.

Characteristics:
• No efficient algorithm is currently known.
• No proof exists that an efficient algorithm is impossible.
• Solving one NP-Complete problem efficiently would solve all NP-Complete problems efficiently.

Importance:
• Widely studied in computer science.
• Frequently appear in real-world applications.

------------------------------------------------------------
WHY STUDY NP-COMPLETE PROBLEMS?

Reason 1: No one has proven that efficient solutions cannot exist.
Reason 2: An efficient solution to one NP-Complete problem would apply to many others.
Reason 3: Small changes in a problem can dramatically change its difficulty.

------------------------------------------------------------
REAL-WORLD IMPORTANCE

NP-Complete problems appear in many practical situations.

Examples:
• Route Planning
• Scheduling
• Resource Allocation
• Network Design
• Logistics and Delivery Systems

Implication:
Understanding these problems helps developers avoid spending excessive time searching for impossible perfect solutions.

------------------------------------------------------------
TRAVELING SALESMAN PROBLEM (TSP)

The Traveling Salesman Problem (TSP) is a famous NP-Complete problem.
Find the shortest possible route that visits every location exactly once and returns to the starting point.

------------------------------------------------------------
TSP EXAMPLE

Delivery Locations:
       B
      / \
     /   \
    A-----C
     \   /
      \ /
       D

Goal: Visit all locations while minimizing total travel distance.

Applications:
• Delivery Services
• Transportation Networks
• Logistics Companies
• Route Optimization

------------------------------------------------------------
WHY TSP IS DIFFICULT

Problem: The number of possible routes grows rapidly as the number of locations increases.
Result: Finding the perfect solution becomes computationally expensive.

Solution: Approximation algorithms are often used to find near-optimal solutions.

------------------------------------------------------------
APPROXIMATION ALGORITHMS

Approximation algorithms provide good solutions when finding the perfect solution is impractical.

Advantages:
• Faster execution
• Acceptable results
• Suitable for large datasets

Example:
Delivery companies often use approximate routes instead of the mathematically shortest route.

------------------------------------------------------------
PARALLELISM

Parallelism is the practice of performing multiple computations simultaneously.

------------------------------------------------------------
WHY PARALLELISM IS NEEDED

Processor speeds cannot continuously increase due to physical limitations.

Problem: Increasing clock speed generates excessive heat and power consumption.
Solution: Use multiple processing cores to perform tasks simultaneously.

------------------------------------------------------------
MULTICORE PROCESSORS

A multicore processor contains multiple processing units on a single chip.

Example:
Core 1 → Task A
Core 2 → Task B
Core 3 → Task C
Core 4 → Task D

Result: Multiple tasks execute at the same time.

------------------------------------------------------------
PARALLEL COMPUTING

Parallel computing divides a large problem into smaller tasks that can run simultaneously.

Example:
Task: Process 1,000,000 records

Sequential Approach: One processor handles all records.
Parallel Approach: Four processors each handle 250,000 records.

Result: Faster execution.

------------------------------------------------------------
MULTITHREADED ALGORITHMS

Multithreaded algorithms use multiple threads to execute different parts of a program simultaneously.

Benefits:
• Faster processing
• Better hardware utilization
• Increased throughput

Applications:
• Operating Systems
• Web Servers
• Scientific Computing
• Artificial Intelligence

------------------------------------------------------------
ADVANTAGES OF PARALLELISM

• Faster execution time
• Improved performance
• Better resource utilization
• Increased system throughput

------------------------------------------------------------
LIMITATIONS OF PARALLELISM

• More complex programming
• Synchronization challenges
• Additional hardware requirements

------------------------------------------------------------
WHY ALGORITHMS MATTER

Benefits:
• Reduce running time
• Save memory
• Improve scalability
• Solve larger problems efficiently
